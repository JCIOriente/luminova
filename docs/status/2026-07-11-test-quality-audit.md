# Test-quality audit — self-mirroring / tautological guards (2026-07-11)

This audit hunted one anti-pattern class across all 202 test files in the monorepo: tests whose expected values are hand-copied from the very source of truth they claim to protect, so they pass while the drift they exist to catch happens silently. The seed of the audit is the siteConfig incident: `tools/scripts/lib/site-config-seed-data.test.mjs` (now deleted) asserted a hand-typed key/type list that mirrored the Zod schema — it could never catch the schema gaining a required field the seed lacked, which was the actual bug. It was replaced (branch `fix/siteconfig-seed-drift`) by parsing the real `SITE_CONFIG_CONTENT` through the real `siteConfigDocSchema` in `packages/types/src/site-config-doc-schema.test.ts:121`. The good-pattern reference is `packages/types/src/role-definition.mirror.test.ts`, which imports both the canonical table and its downstream `.mjs` mirror and cross-checks them. Every finding below was verified by reading both the test and the implementation source — brittle-but-honest tests (literal label assertions that go red on a rename) were deliberately **not** flagged; only false-confidence guards were.

Subtype legend: **1** hand-mirrored expectations · **2** tautology (copy of impl constant) · **3** guard that can't catch its own drift class · **4** over-mocked / vacuous · **5** key-list where a real schema parse was available.

## Clean bills of health

- **`tests/firestore-rules`** — `seed-contract.test.ts` imports the real claim producers and runs them against the real rules in the emulator ("Importing the real producers (not a re-implementation) is the point"); `rules.test.ts` is genuine allow/deny probing except the locked-field enumeration (finding 2). **`tests/storage-rules`** — boundary literals (5 MB + 1, content types) necessarily restate `storage.rules` constants; the rules DSL has no importable constants — acceptable-as-is.

No `expect(true).toBe(true)`, no assertion-free tests found anywhere.

## Patterns & root causes

- **Where drift-blind tests grow here:** (a) **seed/`.mjs` mirrors** — plain-Node ops scripts can't import workspace TS, so catalogs get hand-duplicated (`role-seed.mjs` → fixed with a mirror test; `site-config-seed-data.mjs` → fixed on branch; `cel-seed.mjs` → still unguarded, finding 1); (b) **rules⇄client contract sets** — `firestore.rules` can't import constants, so locked-field/limit lists exist twice with only comments linking them (finding 2, storage limits); (c) **closed-enum pins** — `toEqual([...retyped list])` on catalogs (`ROLES`, `MEMBER_STATUSES`, `ALLY_CATEGORIES`) that add no guard beyond change-detection; (d) **constant echoes** — `expect(CONST).toBe(<copied value>)` where the real invariant (byte budget, behavior at boundaries) goes unasserted (findings 3, 12, 13).
- **The fix recipe, in preference order:** (1) *parse the real artifact through the real validator* (siteConfig pattern); (2) *import both real sides and cross-check* (`role-definition.mirror.test.ts` pattern — the package that owns the canonical owns the proof); (3) *derive expectations from the single source of truth* and loop it to generate per-item probes (locked-field fix); (4) when a literal must stay (stored-data values, rules-DSL boundaries), *comment it as a contract pin* so the next editor knows the failure is the point; (5) assert the *constraint* a magic number encodes, never the number itself.
- **Meta-observation:** the repo's hygiene is well above average — the two strongest patterns (mirror cross-check, seed-through-schema) already exist here; the genuine findings are mostly the *remaining instances that never got retrofitted* after those patterns were invented. The next session is largely "finish the rollout", not "invent a discipline".
